# 评估协议 v2：单切分快循环 + 封存测试集

日期：2026-08-22
分支：feature-restructure
状态：现行有效方案，取代"91 轮 walk-forward 为默认评估"的旧方案
术语约定：只用标准三段命名——训练集 / 验证集 / 测试集。

## 为什么改

旧方案（Issue #8/#12 设计）默认所有评估都跑 91 轮季度滚动重训，单次约 12 小时。
这个成本让日常调优无法迭代。
91 轮的真实价值只是"22 年各区间的成绩分布 + 每季度新鲜模型"，属于测量增强，不是防泄漏的必要条件。
用户既有的工作流（训练集训模型 → 测试/验证段回测调优）在模型层面本来就是样本外的，应予保留。

## 数据集划分逻辑（按用途划分，不按比例）

```
训练集                验证集                 测试集（封存）
2001-01 → 2021-12-31  2022-01 → 2025-07-31   2025-08-01 → 数据末日
只用于拟合模型参数     一切选择动作只许在这里   封存，任何调优不得接触
                      ：调参/筛特征/选label/   每个最终候选只许量一次，
                        挑策略参数，可反复用    量完记入台账
```

边界理由：

- 训练集吃满最长历史（含 2001-2008），让模型见过多种市场制度。
- 验证集约 3.5 年，沿用习惯的"尾部窗口回测"方式；模型从未训练过这段，模型层面是样本外。
- 测试集取最近 12 个月，因为它离实盘最近、最能代表未来；它从不出现在任何训练、调参、特征筛选、策略挑选中。

## 防泄漏职责分工（切分频率与防泄漏无关）

| 问题 | 修复位置 |
|---|---|
| 特征含未来数据 | 特征管线层：逐日生成、只用当日及之前数据 |
| 幸存者偏差 | 数据层（#5）：含退市股的全量数据 |
| 参数/特征/label 在验证集上反复挑选 | 测试集隔离：最终成绩只在测试集量一次 |
| 评估噪声（一切划分都有运气成分） | 测试集 + 验证集内部多年度对照，运气无法消除但可以隔离测量 |

## 日常工作流（快循环）

1. 单次训练：训练集数据，LightGBM 5 折 TimeSeriesSplit + L1 LR stacking（架构不变），约 1-2 小时。
2. 在验证集评估（PR-AUC、回测），随便迭代。
3. 产出 1-2 个最终候选后，在测试集各量一次，记台账，定稿。

执行命令（2026-08-22 起）：

```bash
# 训练集 ≤2021-12-31，验证集 2022-01-01→2025-07-31；测试集由脚本自动封存（打分触及即拒绝）
MALLOC_ARENA_MAX=4 uv run python scripts/run_walk_forward_train.py --single-split
```

模型与验证集预测保存在 `models/single_<train_end>_<score_start>_<score_end>/`。
脚本启动时强制校验缓存指纹（管线版本 + 日 CSV 数量/最新修改时间），缓存过期直接报错拒绝训练。
